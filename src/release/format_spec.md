# Archival evidence envelope version 2

This is an explicit replacement for the absent companion specification. It preserves the supplied byte ledger, algorithms, batches and checkpoints. The local experiment is P_H_LINUX_3, not a replication of native macOS Protocol 1.4. Linux fsync on a container overlay is a software call contract only. No physical durability, APFS, trusted timestamp or independent preregistration is claimed.

All integers are unsigned big endian. The Python struct layouts below are normative. All reserved fields must be zero. An object frame is `>4sBBHII` (16 bytes): PQOB, version 2, object type, reserved, object ID, body length. Types are manifest 1, enrollment 2, token 3, stored tree 4, inclusion path 5. Unknown, duplicate, extraneous, truncated and out-of-order proof objects are rejected. Header and lengths are bounded before allocating.

Archive and proof header `>8sBBBBIIIQ32s` is 64 bytes: PQARCH02, version 2, arm (N=1 E=2 D=3), mode (archive=0 full=1 selective=2), final generation, total records, batch capacity 4096, selected record ID (0xffffffff for archive/full), modeled epoch, history identifier. The trust policy externally supplies the expected history, record count, arm, epoch and complete enrolled public keys. An untrusted proof does not enroll its own keys. A distinct random 32-byte history ID prevents cross-history substitution.

Manifests are ASCII-only canonical UTF-8 JSON (`sort_keys=True`, separators comma/colon, finite values, no duplicate fields) padded inside a `padding` string to exactly 1024 bytes. They include record ID, payload hash, code/configuration/environment digests and dependency identities. Frame ID equals record ID. Canonical serialization is checked independently at verification. Synthetic manifests are byte-identical across arms in a matched block; fresh cryptographic keys and history IDs are independent.

Signed token header `>8sBBBBIQQ16s20s` is 68 bytes: PQTOKEN2, version 2, arm, branch (primary=0 redundant=1), algorithm (ECDSA=1 MLDSA=2 SLHDSA=3), generation, subject (record for N, batch for E/D), issue time, key ID, first 20 bytes of history ID. The signed message appends target and predecessor digests, each 32 bytes for primary or 48 for redundant, yielding 132 or 164 bytes. Predecessor is all zeros at generation zero, otherwise H(0x02 || complete previous token BODY). Primary generation zero uses ECDSA P256 with SHA256 and fixed r||s. Later primary generations use pure ML-DSA-65; redundant generations use pure SLH-DSA-SHA2-192f. Empty context. Key rotation at every generation. Issue times are epoch + 100*generation under the honest modeled clock. Expected issue times and deadlines are externally supplied policy, never wall-clock attestation.

Enrollment body `>8sBBBBIQ16s20s3s` is 63 bytes followed by raw public key: PQKEY002, version 2, arm, branch, algorithm, generation, issue time, key ID, history prefix, reserved zeros. Key ID is first 16 bytes SHA256(PQKID002 || raw public key). Public keys are ECDSA uncompressed point (65), ML-DSA-65 (1952), SLH-DSA (48). Framed enrollment sizes are therefore 144, 2031 and 127. Enrollment records are matched against external honest enrollment. No self-signed certificate chain is implied.

Leaf H(0x00 || global record ID as uint64 || manifest), internal H(0x01 || left || right), with SHA256 on primary and SHA384 on redundant. Odd final nodes are promoted unchanged, never duplicated. N targets are leaf hashes. Tree body has 24-byte `>BBBBIIIII` metadata: version, branch, hash width, reserved, batch ID, first record, leaf count, node count, reserved. Store leaves, then newly computed internal nodes in level order; promoted nodes are not stored twice. Total 2*b-1. Inclusion paths have the same metadata layout with sibling count in the node-count field and only actual siblings bottom up; orientation follows the record index and promoted-node recurrence. Tree/path frame IDs are (branch<<28)|batch.

Enrollment frame IDs are (branch<<28)|generation. Token frame IDs are (branch<<28)|(generation<<20)|subject, limited to n<2^20 and generation<256. Type is part of object identity. Proof order is header, manifests (all in index order or selected one), enrollment records by generation then branch, paths by branch if selective E/D, then tokens by generation, branch, subject. Full proofs omit trees and paths and reconstruct roots. Every required token is audited, including both D branches. Acceptance requires every requested subject to have at least one complete policy-eligible branch. Structurally missing required audit objects are rejected even when another branch might suffice; a separate policy failure can make a cryptographically valid branch ineligible. All branches are still cryptographically audited.

Archive order is header, all manifests, then each generation's primary enrollment followed by primary subject tokens, then redundant enrollment and redundant tokens if D. At generation zero each retained tree is immediately before its corresponding token. One writer fsyncs on reaching 4MiB and each nonempty generation end. File creation and parent-directory fsync precede campaign timing. Complete-path availability is assigned to the first successful barrier containing its final token. These traces are measurement instrumentation, never proof of historical issuance.

Timing starts before opening an already constructed proof and ends after its acceptance decision; file reads, parsing, enrollment lookup, external hashes and signatures are included. Payload reads and proof construction are separate. File opening/closing and orchestration overhead are inside measured time but may be residual model error: there is no fitted intercept. Warm OS cache is established by sequentially reading proof bytes before the measured call; no persistent verifier caches are retained. One timed repetition per condition. Query order is randomized per history after all six generations are written.

The verifier API requires an external (renewals, query mode, requested record ID) tuple. The proof header must match it exactly. No implicit request is inferred from untrusted proof bytes. Calling without an external request fails. This contract correction is protocol 3; the binary envelope remains version 2.
